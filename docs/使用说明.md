# 进销存与往来管理系统 V1.1 使用说明

## 一、安装、登录与修改密码

1. 双击“进销存管理系统安装程序-1.1.0-x64.exe”，按安装向导选择安装位置。
2. 安装后通过桌面或开始菜单的“进销存管理系统”快捷方式打开独立客户端。
3. 初始用户名为 `admin`，初始密码为 `admin`，直接登录即可使用。
4. 登录后点击右上角账号菜单 → “修改密码”，输入原密码和新密码。修改后使用新密码重新登录；重启或升级不会重置已修改的密码。
5. 在“系统管理 → 企业与业务参数”中设置软件名称、品牌简称、Logo 和企业名称。软件名称与企业名称分别管理；新密码需为 8～72 字节，包含数字和非数字字符。

内置免费可商用的 Noto Sans SC 字体（OFL 1.1）和 Element Plus Icons 图标（MIT），离线加载；完整声明随安装程序附带，客户端“帮助 → 第三方许可证”可以打开。安装包与快捷方式名称可在源码 branding.json 中配置后重新打包，详见《字体图标与品牌配置》。

运行要求：Windows 10 / 11，64 位。安装包自带客户端运行环境，使用独立程序窗口，无需 Chrome、Edge、WebView2、Go、Node.js、Python 或数据库服务，安装后可离线使用。

客户端关闭时会安全停止本地数据服务。请先保存正在编辑的单据。再次启动保留原有账号、授权和经营数据；重复启动会回到已有客户端窗口。

默认数据库位置为 `%APPDATA%\RuilianERP\data\ruilian.db`。例如 `C:\Users\用户名\AppData\Roaming\RuilianERP\data\ruilian.db`。安装目录与数据目录分离，升级和卸载均保留经营数据库；可从“文件 → 打开数据目录”进入。

## 试用提示与授权入口

未正式授权时，登录页和每个业务页面顶部均显示试用提示，包含剩余天数、试用结束时间及“立即授权”按钮。点击后直接进入软件授权页面；在登录页点击则登录后自动进入授权页面。授权到期仍保留查看、导出、备份和授权入口。

## 二、推荐初始化顺序

先建立商品、客户、供应商、仓库与库位，再录入期初库存、期初应收和期初应付。最后开始正式采购、销售和收付款。

基础资料的编码可以留空，由系统生成。已有库存流水的商品不允许改变单位、批次及序列号管理方式；资料停用保留原始数据和历史引用。

期初库存按商品、仓库、库位、批次逐维度录入；已有库存流水的维度不能再次初始化。期初往来须在该单位产生正式账单前录入。期初负金额代表贷项余额。

## 三、单据流程

通用操作为“保存草稿 → 提交审核 → 审核入账”。草稿可编辑；提交后可退回草稿；审核后不可直接修改。

- 采购订单审核后不入库、不产生应付。打开订单并选择“生成下游单据 → 采购入库”，可部分执行。也可直接新建采购入库。
- 销售订单审核后占用指定库存。关联订单生成销售出库时释放对应占用。未关联订单的出库不能占用其他订单的库存。
- 采购入库审核增加库存、形成应付；销售出库审核扣减库存、形成应收。
- 零售或勾选“现销”的销售，审核时同时生成独立的客户收款单并核销本单应收。
- 采购 / 销售退货与换货必须选择原单。原单明细只允许累计执行至原数量，同一序列号不能重复退回。
- 换货单同时填写退回方向和换出 / 换入方向，按差额生成往来账。退回商品沿用原单价格；销售退回按原出库成本恢复库存。
- 调拨选择不同的调出与调入仓库，审核时一次完成库存及成本转移。
- 盘点可“提取账面库存”，修改实盘数量后审核。盘点保存后库存发生变化，会拒绝审核；需退回草稿、重新保存核对后再提交。
- 组装 / 拆分须有出库和入库明细。出库组件按移动平均成本计价，成本分配给产出；产出参考价用于确定分摊权重，未填时按数量分配。
- 委托发货转入“委托仓”，不产生应收。由委托发货生成代销结算后才确认销售与应收；未销售商品通过委托退回返回原仓。

数量、单价最多四位小数，账款金额为两位小数。正式合计以保存后显示的服务端计算结果为准。

## 四、收付款、核销与退款

在往来管理中切换“客户应收 / 供应商应付”。新建客户收款或供应商付款，审核后自动按账单到期日、编号顺序核销，允许部分核销；超出账款的资金成为预收 / 预付。

后续可在“收付款 / 预收预付”中选择资金单“核销”，填写一张或多张账单的核销金额。核销记录可填写原因撤销，收付款单仍保留。

退货先抵扣原单的未核销账款，超出的退货金额形成贷项。贷项可以通过“退货贷项冲账”抵扣同一单位的其他正向账款。退款先处理退货贷项，再抵扣未使用的预收 / 预付，不能超过可退余额。

应收应付余额由单据产生，不提供直接改余额的功能。“往来对账”显示期初、期间发生、收付款及逐笔余额。账龄按到期日分为未到期、1–30、31–60、61–90、91–180 和 180 天以上。

## 五、价格与信用控制

销售自动定价依次采用：客户专属价、客户等级价、限时促销价、数量阶梯价、商品销售价、商品指导价。零售可使用商品零售价。同类规则按优先级及起订数量匹配。未命中专门规则时可应用客户基础折扣。

已关联订单默认沿用原订单约定价。具备“手工改价”权限的用户可调整销售价格。后端在审核时再次执行最低售价、信用额度和逾期控制。信用额度为 0 表示不限制。

“预警中心”汇总库存不足、超限、呆滞、信用超额、应收逾期、应付即将到期和最低售价异常。确认预警会留下记录；业务数据变化时可产生新提醒。

## 六、红冲和关闭

草稿与待审核单据可以作废。已审核单据需要纠正时，优先使用真实退货 / 换货业务。

没有下游单据、核销或后续库存流水时，可以填写原因“红冲”。系统保留原单，生成独立红冲凭证和反向流水。存在后续库存流水时拒绝红冲，防止覆盖后续平均成本；需要先处理相关业务。

关闭已审核订单会释放尚未执行的库存占用；已经执行的业务保留。现销单红冲前须先红冲其自动生成的收款单。

## 七、用户与权限

内置系统管理员、业务经理、仓库管理员与财务人员角色。可新增角色并配置模块查看、录入、审核、手工调价、金额、成本、备份和系统权限。

业务数据范围支持全部 / 仅本人；仓库范围支持全部或指定仓库。单据、往来与报表检查业务范围，实物库存按仓库共享。金额和成本在接口、表格、打印及 CSV 导出中分别受权限控制。修改账号或角色后，相关用户需要重新登录。

## 八、报表与导出

报表中心支持销售 / 采购日、月汇总，商品、客户、供应商、业务员及渠道排行，退货分析、库存余额、盘点差异与账龄。经营分析提供净销售、净采购、净收付款、毛利、回款率及库存周转。

当期回款率采用当期净收款 / 净销售口径，包含预收及历史账款回款，可能超过 100%。库存周转次数为当期销售成本 / 期初期末平均库存；周转天数按选定期间实际天数计算。平均库存不为正时不计算周转。

负库存默认禁止。若管理员开启，则按现有平均成本或参考采购价暂估，回补时产生独立成本差异，计入经营毛利。序列号商品及已被订单占用的库存不允许透支。

CSV 文件采用带 UTF-8 标记的格式，可以用 Excel 打开。导出使用全部匹配数据；表格分页不限制单据和报表导出的范围。各单据详情提供打印。

## 九、数据目录与备份

默认数据目录为 `%APPDATA%\RuilianERP\data`：

- `ruilian.db`：SQLite 主数据库。
- `ruilian.db-wal / ruilian.db-shm`：运行中的事务日志与共享信息，运行期间不要删除或单独复制主数据库代替备份。
- `.installation.json / .installation.key`：本机安装完整性记录，须与原数据目录一起保留。
- `backups`：软件生成的一致性 SQLite 快照及 SHA-256 清单。
- `logs`：运行与错误日志。

在系统管理的“备份恢复”点击“立即备份”。每份备份执行 SQLite 完整性、外键、库存流水、占用、往来核销和序列号一致性检查，并计算 SHA-256；“验证”会再次打开备份执行恢复可读性检查。

默认自动快照间隔 15 分钟，快照保留最近 192 份；每日备份 14 份、每周 12 份、每月 12 份，可配置。手动备份不自动清理，独立位置的副本由该介质的管理策略保留。自动任务仅在客户端运行期间执行，失败最多重试 3 次并记录异常任务。

必须根据企业实际条件配置独立磁盘与异地目录，例如 `E:\业务备份`、`\\备份服务器\企业备份\业务备份`。建议至少保留本机、独立介质、异地三份。程序不能将同一磁盘上的几个目录变成独立介质，未配置时会在界面提醒。

## 十、在客户端内恢复数据库

1. 先保存当前正在编辑的单据，找到软件生成的 `.sqlite` 备份。
2. 在“系统管理 → 备份恢复”点击“从备份恢复”，也可使用顶部“文件 → 从备份恢复”。
3. 选择备份文件，核对路径后点击“验证并恢复”。
4. 客户端先验证备份，再自动停止数据服务；将原数据库、WAL、SHM 和安装记录保存至 `pre-restore-日期时间` 目录，再执行恢复。
5. 客户端自动重新打开，核对库存、应收应付、最近单据和软件授权。

备份损坏、账实不一致或来源仍有 WAL 时会拒绝恢复。恢复操作写入审计日志。若启动时数据库损坏，可在客户端启动错误窗口选择“从备份恢复”。

新机器仅恢复数据库时会生成本机安装标识，并进入授权异常保护；经营数据仍可查看、导出、备份，请使用新 Installation ID 联系发行方重新绑定。

建议至少每月在单独测试数据目录实际恢复一次，核对核心业务。不要只依赖数据库所在磁盘的备份文件。

## 十一、试用和永久授权

首次初始化后自动试用 10×24 小时。试用中可使用全部功能。永久授权使用离线数字签名，与 Installation ID 绑定，不设置到期时间。

在“系统管理 → 软件授权”复制 Installation ID，交给发行方获取授权码，再粘贴授权码或导入 `.license` 文件并激活。

试用到期或授权异常只限制新增和变更业务，不删除数据，也不禁止登录、查看、导出、备份、恢复和激活。检测到明显时间回拨时，需要校准系统时间并重新输入有效授权码。

发行方私钥不在客户安装包或业务数据库中。离线授权不能阻止拥有系统管理员权限的所有篡改行为，但会检查签名、安装标识、版本范围、最近运行时间和安装记录完整性。

## 十二、高级运行与故障排查

日常使用通过客户端窗口完成，无需命令行。以下命令供维护人员在已安装的程序目录运行：

```powershell
# 在单独数据目录启动客户端
.\进销存管理系统.exe --data-dir "D:\业务数据"

# 仅验证备份
.\进销存管理系统.exe --no-browser --verify-backup "E:\备份\ruilian.sqlite"

# 在客户端停止后执行离线恢复
.\进销存管理系统.exe --no-browser --data-dir "D:\业务数据" --restore "E:\备份\ruilian.sqlite"
```

故障信息位于数据目录的 `logs`。如启动失败，请保留完整数据目录和日志。客户端使用本机回环连接访问随安装包附带的数据服务，这不会打开系统浏览器，也不要求互联网连接。

从早期浏览器测试版升级时，原 EXE 旁的 `data` 不会自动删除或覆盖。可先在旧版生成备份，再通过新客户端“从备份恢复”导入，并核对账号、经营数据和授权。
